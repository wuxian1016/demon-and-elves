公开仓库，不用登录就能克隆或下载。给接手的 AI（Codex 等）和开发者继续改用。

- 克隆：`git clone https://github.com/wuxian1016/demon-and-elves.git`
- 只下载最新版压缩包（不用 git）：<https://github.com/wuxian1016/demon-and-elves/archive/refs/heads/main.zip>

## 这是什么

当前 `main` 是 **R12-PF2（含 T1）**。它基于 11-24 交接站「操作提示」版（开发客户端 6cfa42d），针对「满电脑队友时卡顿、发热、不能稳 60 帧」做了性能修改。

| 标签 | 内容 |
|---|---|
| `r12-pf2-t1` | **当前版本**。在 `r12-pf2` 上加 T1：全屏半透明遮罩在 CPU 画布的手机上改为贴同色整屏图。开机检测到 CPU 画布、而且逐像素核对通过才启用，显卡画布不启用。遮罩改动在所有对比里像素和状态都与原版一致。**还没有在 iPhone 上验收。** |
| `r12-pf2` | 上一版：M1、M2、L4 + 版本标签。**更正**：那时说「像素全部一致」不完整，L4 在一种开局时机下会让部分树的像素有轻微差别（见下文和报告 4.4）。 |
| `r12-6cfa42d` | R12 原版底稿：11-24 交接站五个分片还原出的开发客户端，1,460 个文件逐个核对一致（`source.sha256.r12`），原样提交，没有修改。 |
| `cow8d-pf1` | 上一轮：COW8D 上的发热、长帧、内存修改（R12 已经包含）。 |
| `cow8d` | 更早的原版底稿 COW8D。 |

看本轮全部改动：`git diff r12-6cfa42d r12-pf2-t1 -- client`

## 改了什么

| 代码 | 文件 | 改动 | 画面/玩法 |
|---|---|---|---|
| M1 | `client/network/mini-demon-follow.js` | 小恶魔找攻击站位时，「被地形挡住」只会让代价 +70。其余代价已经不可能胜出的候选点，就不再做视线检测 | 选出的位置完全一样 |
| M2 | 同上 | 小恶魔绕开同伴的路径搜索：先看这条边能不能让到达代价变小，不能就不做通行检测 | 路线完全一样 |
| L4 | `client/art163/terrain-edge-prefetch.js` | 镜头快速移动时（切镜、首次遭攻击聚焦、回基地、拖地图），按移动方向提前画好 0.5 秒内会进入画面的地形块。每帧最多 2 块，只在本帧地形耗时不到 4 ms 时才画。慢速保持 PF1 的做法 | 玩法不变。在一种开局时机下，第 60 秒切镜之后部分树的像素有轻微差别（位置不变，每像素平均差 3–4 级，肉眼看不出）。**保留还是去掉，等用户决定** |
| T1 | `client/js/main.js`、`client/art163/game.js`、新文件 `client/art163/screen-tint.js` | 10 处全屏半透明遮罩：准备期浅蓝、救援提示、菜单和面板底色。开机在首页或加载画面里分 15 帧检测，「CPU 画布」且「10 种颜色贴图与铺色逐像素相同」才启用贴图，否则照原样铺色 | CPU 画布下像素逐个相同；显卡画布不启用 |
| 标签 | `single-player-build.js`、`asset-config.js`、`release.json` | 首页标签改为「R12-PF2-CLAUDE」，诊断版本号加 `-PF2` | 只有首页那行字 |

效果（Mac 测量，只能当前后对比）：
- 后期逻辑每次更新：平均 1.06 → 0.90 ms，最慢的 1% 4.15 → 2.67 ms；地形碰撞查询减少 37%。
- WebKit、CPU 画布模式、同一局后期混战：每帧 5.89 → 5.36 ms，JS 部分 −34%。
- 开局第 60 秒恶魔苏醒切镜：超过 16.7 ms 的帧 26 → 0（L4）。
- T1，WebKit、CPU 画布：
  - 准备期每帧 5.81 → 5.13 ms；
  - 打开升级面板时 4.61 → 3.67 ms；
  - 绘制进程 CPU 时间 −12%；
  - 遮罩显示期间多占约 5.3 MB 内存，3 秒不用即释放。

T1 在真机上是否启用：在调试控制台执行 `screenTintStateBN.probeLog()`。
- `why` 为 `"cpu"`：已启用；
- `"not-slower"`：显卡画布，不启用；
- `"pixels-differ …"`：像素核对没通过，不启用。

细节见报告。

## 接手先做

1. 校验：`cd client && shasum -a 256 -c ../source.sha256.r12-pf2`，应 1,461 行全部 OK。
2. 依次读：
   - `perf-report/R12-PF2/检查与优化报告.md`（尤其 4.4、4.5 节和第 5 节「还没解决的」）；
   - `handoff-r12/START-HERE.md`；
   - `handoff-r12/guides/操作提示接手指南.md`。
3. 准备测试环境：在 `perf-tools/` 里 `npm install`。
4. **做前后对比时一定要用确定性模式**：
   - Node：`VTIMERS=1`，图片就绪通知在固定帧发出（`detgfx.cjs`）。否则 Boss 素材的加载时刻会随机器忙闲变化，同样操作跑两次局面会分叉。
     - 玩法是否变了：`VTIMERS=1 node updbench.cjs <client> 720`，比较两版的状态指纹。
     - 画面是否变了：`compare.cjs` 比较逐秒状态和整屏像素。
   - WebKit：`det=1`。证明像素一致只用 CPU 画布（`WK_NOACCEL=1`）。显卡画布下这个测试工具连原版自己都不能稳定复现。另外建议加 `homeframes=60`（开局前在首页停 1 秒）再比一次：L4 的像素差别只有这样才测得出来。

## 用户定的硬要求（必须遵守）

- 目标：满电脑队友也要稳 60 帧，不卡顿、不掉帧、没有长帧，不明显发热，全程不出现内存警告。
- 严禁用降低画质、限制帧率、删特效或玩法来换性能；严禁把解码停顿挪到首次操作或回前台时。
- 不擅改已定数值和定稿素材。改素材的加载时机或分辨率，先问用户。
- 纯性能改动必须证明画面像素和游戏状态与改前一致；有变化就写清楚变了什么。
- 没在 iPhone 上测过的指标不能说达标。
- iOS 高性能模式必须保持开启。真机测试先确认诊断记录里 `runtime-mode` 的 `highPerformance` 是 `true`。

## 待办（按优先级）

1. 真机对比 r12-6cfa42d 与 r12-pf2-t1：同一台 iPhone 12，单人、8 电脑、疯狂难度，各 30 分钟。
   - 记录 FPS、顿卡时点、温度、耗电和内存警告；
   - 顺便看 T1 的检测结果。
2. **L4 保留还是去掉，等用户决定**：保留则切镜不卡，但切镜后部分树像素有轻微差别；去掉则画面逐帧一致，但切镜长帧回来。去掉的办法是把 `client/art163/terrain-edge-prefetch.js` 换回原版。
3. 更快的镜头移动（1 秒约 4,000 单位，第 70–74 秒那类）仍会顿一下。原因是地形缓存 16 MB 装不下出发点、路上和目的地。可以临时加缓存，或放慢这类镜头，都要用户同意。
4. CPU 画布下绘制仍是大头（M6 上后期每帧约 5 ms）：建筑层、顶部界面、单位特效。

## 注意

- `client/js/main.js` 第一行注释说它由 `build-wechat125.cjs` 从共享 `js/` 源码生成，但交接包里没有那份源码，所以修改直接改在 `client/`。
- 微信预览主包只剩约 1,700 字节余量（见 `handoff-r12/incremental/READ-ME.md`）。本轮主包比原版净增 31 字节：M1、M2 和标签 +100，T1 让 `main.js` 少了 69。遮罩模块放在 art163 分包里。改主包里的文件前先算好大小。
- 测试和预览不要读写真实存档，也不要打开真实广告。命令行出预览码前，要在微信开发者工具里打开「设置 › 安全设置 › 服务端口」。
